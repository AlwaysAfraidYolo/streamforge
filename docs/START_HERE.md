# Начало работы

Это подготовленное окружение для обучения, а не законченная платформа.
Инфраструктуру настраивает ментор. Ты будешь постепенно писать модели событий,
приём пакетов, работу с БД и ETL. Наличие папки не означает готовность функции.

## Запуск

Открой Docker Desktop, затем терминал в папке проекта:

```sh
make up
```

Команда сама создаст локальный `.env`, соберёт API и поднимет PostgreSQL, Redis
и S3-хранилище. Пароли генерируются автоматически и не попадают в Git.
Первый запуск скачивает образы и может занять несколько минут.

Открой http://localhost:18000/docs — здесь список готовых HTTP-методов.
Сейчас это только `/live` и `/ready`. Ingestion ещё не реализован.

```sh
make smoke       # запись и чтение тестовых данных в хранилищах
make test        # проверки инфраструктурного кода
make down        # остановить контейнеры, сохранив данные
```

Не используй `docker compose down -v`: флаг `-v` удаляет данные этого стенда.

## Когда дойдём до аналитики

```sh
make analytics
```

Появятся ClickHouse и Airflow. Airflow доступен на http://localhost:18080.
Пользователь — `mentor`. Сгенерированный пароль лежит только в volume Airflow:

```sh
docker compose exec airflow cat /opt/airflow/simple_auth_manager_passwords.json.generated
```

Не публикуй вывод этой команды. Демо-DAG `infrastructure_check` проверяет доступ
к API; бизнес-ETL ещё не написан. Standalone — режим локального обучения.

## Редактирование Python

Твой Python 3.14.3 подходит для локального окружения. В контейнере закреплён
патч-релиз 3.14.7. Системный Python не переустанавливаем.

```sh
uv sync --frozen
```

В редакторе выбери `.venv/bin/python`. Код `app/` подключён к контейнеру:
после сохранения файла API перезапускается автоматически.

## Первая учебная задача

Пока не нужно писать Docker, миграции или ETL. Сначала вместе разберём:
1. Что возвращает `/live`.
2. Почему `/ready` дополнительно обращается к PostgreSQL и S3.
3. Чем «процесс запущен» отличается от «сервис готов принимать данные».

После этого ментор даст одну задачу на модель события, с примером входа,
ожидаемым результатом и необходимой теорией. Срок 14 дней не является дедлайном.
